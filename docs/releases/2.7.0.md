# scandalous 2.7.0

## Adopting humane-ruby v0.9.0's full API rethink

`humane-ruby` dropped its instantiated-formatter shape entirely in `v0.9.0`
-- `Humane::SizeFormatter.new.string(from_byte_count:)` and
`Humane::TimeFormatter.new(approximate: true).string(at:, relative_to:)` are
gone, replaced by class methods `Humane::SizeFormatter.human_size` and
`Humane::TimeFormatter.time_ago` (see `humane-ruby`'s own `docs/COWORK.md`
`v0.9.0` entry for the full cross-repo rationale). `web.rb`'s `human_size`/
`time_ago` helpers are updated to call the new API; no change to
`views/listing.erb`, which only ever calls the helpers, not `Humane`
directly.

`time_ago`'s `approximate: true` is no longer passed explicitly -- it's
`humane-ruby`'s own default as of `v0.9.0` (matching ActionView's own
always-on-past-the-hour behavior), so this app's rendered output is
unchanged. `HumanSize`'s rounding also picked up a correction toward 3
significant figures (fixes some GB-scale/zero-byte/byte-scale cases) --
doesn't affect this app's own fixtures (`"80 KB"` for a ~79,992-byte file),
so `spec/web_spec.rb` needed no changes.

## Upgrading

`Gemfile`'s `gem "humane"` now pins `"~> 0.9"` -- `humane-ruby` `v0.9.0` is
tagged, pushed, and published to RubyGems
([release](https://github.com/woodie/humane-ruby/releases/tag/v0.9.0)).
Run `bundle install` to pick it up.

No other user-facing changes.
